# 研究总结（2026-11-03 – 11-06）

一台 Steam Frame（SteamOS 0.4.5 vr，骁龙 8 Gen 3，16 GB），PC 版 VRChat + EAC，Proton Experimental x86 + steamac 补丁版 FEX。
VR 模式，每轮进世界后 5 分钟，fps 和每帧 CPU / GPU 时间来自 SteamVR 统计（`vrcmd --stats`）。

## 有效，已进 frame-vrc

| 优化 | 效果 |
|---|---|
| 补丁版 FEX（eac） | 前提：没有它 EAC 起不来 |
| CPU 拓扑 16 | 必须：改成 8 时可用内存最低只剩 260 MB |
| DXVK 编译线程 4 | 游戏 CPU 约 −15% |
| 关掉 tabtip.exe | 约 −135 MB，可用内存平均 +200 MB |
| FEX MaxInst 500 | 游戏内存 −0.65 GB、zram −1.9 GB；帧数约 −10% |
| FEX 代码缓存只给 VRChat | Wine 辅助进程 −640 MB，帧数不变 |
| DXVK 显存上报 1 GB | 生效（Unity 看到 1024 MB），人多的世界里的效果未测 |
| 桌面镜像窗口 640×480 | 体感小改进（未 bench） |
| **DFR（1920，作者默认参数）** | 重负载世界帧数约 +15–25%、GPU 每帧 −3–4 ms；轻量世界在噪声内；内存不变 |

## DFR 实测

重负载世界（视频播放器、AI NPC、复杂着色器），1920，固定注视点，按时间顺序：

| 轮 | off | def | ext | off | ext | def |
|---|---|---|---|---|---|---|
| fps | 16.5 | 20.9 | 18.9 | 13.1 | 14.8 | 14.8 |
| GPU ms/帧 | 35.7 | 31.5 | 34.7 | 43.4 | 38.7 | 39.5 |

第二轮整体变慢（温度 97–99 °C、世界里的动态内容），所以看相邻的轮：off → def +27%，off → ext +13–15%。可用内存最低 1.45–1.77 GB，开关 DFR 一样。

轻量世界：帧数都锁在约 36（SteamVR 72 Hz 的一半），1920 开 DFR 只少 0.1–0.7 ms GPU；1440 / 1600 开 DFR 没有收益。

DFR 参数和理论上少着色的像素（单眼，只算双眼并排的主 pass；实际收益远小于理论值，阴影、后处理、CPU 不受影响）：

| 名字 | R1 / R2 / 外围 | 1×1 清晰区 | 少着色 |
|---|---|---|---|
| def | 0.2 / 0.4 / 2×2 | 12.6% | 65.6% |
| wide | 0.2 / 0.35 / 4×4 | 12.6% | 77.0% |
| ext | 0.1 / 0.1 / 4×4 | 3.1% | 90.8% |

## 排除

| 方案 | 结果 |
|---|---|
| Vulkan thunk | VR 里 SteamVR 的 x86 客户端提交第一帧时崩；桌面模式 CPU 约 −10% |
| 关 FEX TSO | 约 35 秒内崩溃 |
| 关 FEX HalfBarrier TSO | 没有收益 |
| Mesa 的显存上报上限 | 只在原生侧生效，x86 路径上不生效 |
| DFR DLL 放游戏目录 | `VRChat.exe` 启动 0.5 秒在 Wine 加载器里崩；必须放 Proton 自己的 DXVK 目录 |
| DFR 在 1440 / 1600 | 没有 / 很小的收益 |
| DFR ext | 1920 时不比 def 快，余光有马赛克（实机体感可接受） |
| 分辨率 ≤1056 | 能跑，画质太差，只作应急 |

## 未测

- 人多的世界里 1920 的内存（单人重负载世界还有约 1.5 GB）。
- 世界里视频播放器的硬件解码（现在是模拟的 x86 软件解码）。
- 玩之前重启头显 / Steam 能省多少（Chromium 进程越跑越大）。

## 测量注意

- 不要读游戏进程完整的 `/proc/<pid>/smaps`（会卡顿），用 `smaps_rollup`。
- 无人值守测试前关掉头显休眠：待机会暂停渲染、卡住登录。
- 世界里有动态内容和温度时，同一设置两轮能差 2 ms 以上；至少交替跑两轮再下结论。
